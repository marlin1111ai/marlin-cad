# Known Fixes

Quick symptom → fix lookup. See [CLAUDE-LESSONS.md](../CLAUDE-LESSONS.md) for the full detail behind each entry (linked by heading text below).

- **Slot cavity passes watertight check but is sealed shut** → raycast the exported STL, don't trust mesh checks alone; check the cap-detection filter's epsilon (use `1e-4` for float32-derived data). See "Watertightness checks cannot detect a sealed-shut pocket; raycast the exported STL" and "EPS tolerance pitfalls: match the tolerance to the data's noise floor".
- **A raycast test fails at exactly one sample coordinate, and that coordinate is a face plane** → the ray is grazing that face's own boundary edge, which reports an extra crossing and breaks parity counting; the geometry either side of the plane is correct. Bracket the plane (sample just above and just below it) rather than sitting on it, and do not loosen the assertion. Seen on the Mounted Socket Tray's slot-channel test at exactly the tray-top plane — see `reference/reports/mounted-socket-tray-build.md` step 5.
- **CSG subtraction leaves open boundary edges** → the cutter reaches the target's surface; use a boundary-rep instead of runtime CSG. See "Prefer boundary representation over runtime CSG for cuts that reach a surface".
- **False non-manifold edges on an OpenSCAD-baked mesh** → weld with `merge_vertices(digits_vertex=6)` and drop the triangles the merge degenerates. See "EPS tolerance pitfalls: match the tolerance to the data's noise floor".
- **Seam is non-manifold only at larger sizes** → ULP mismatch between two construction paths; build both sides of the seam through the same call path, and push exact literals for arc endpoints. See "The exact-stitch vertex contract: shared seams must be bit-identical doubles".
- **Printed slot pockets clogged / thin internal gap fused shut** → the slit is below printable line width; design it out rather than modeling it thinner. See "Slicer slit fusion: sub-printable internal gaps fuse and ooze".
- **PegPlate hangs mirrored on the wall** → `pegs[].x` is specified in as-mounted view space; do not remove the `normalizedPegs` mirror step. See "Front-face x-addressed features are specified in as-mounted view space; geometry mirrors internally".
- **Mounted Socket Tray pocket typed at a small X appears/prints near the RIGHT end** → the mounted tray needs the same as-mounted mirror the PegPlate has; `normalizedPockets` mirrors `x_geometry = plateWidth - x_viewed`. Do not remove it, and do not "harmonize" it with the flat tray, which is correctly unmirrored: the flat tray is standalone with no fixed viewing side, while the mounted tray has exactly one valid mounting orientation, so its geometry x = 0 is the mounted viewer's RIGHT edge. The trap is that this bug is invisible to every geometry check — the mesh is watertight, manifold and correct, just handed to the user in the wrong x convention — and invisible to a symmetric test layout, so pin it with an asymmetric pocket. Fixed 2026-09-06; see DECISIONS.md's corrected entry.
- **A "match the pre-change output" code path passes every in-suite test (manifold, exact-directed-edge, `toEqual` against its own radius-omitted call) but still doesn't reproduce a frozen reference file byte-for-byte** → an in-suite comparison only proves the new code is internally consistent with itself, not that it matches an external, already-committed file; regenerate the frozen reference file with the new code and diff it (`git status`/`git diff`) instead of trusting the test suite alone. Caught in the Mounted Socket Tray's Corner Radius build (`4be03de`): moving two `pushCap` calls (bottom face, mounting face) to after the new radius branch, instead of leaving them at their original position between the end caps and the tray-top face, silently reordered emitted triangles with identical topology — manifold and exact-directed-edge checks stayed green. See `reference/reports/socket-tray-rounding-build.md` step 5.
- **Bumping the version in `package-lock.json` corrupts unrelated dependencies** → the version string being replaced also appears on transitive dependencies. Bumping off `1.3.0` matched six lines, not two: `es-errors`, `expect-type`, `get-intrinsic` and `tiny-async-pool` all sit at `1.3.0`, and one of them shares the exact indentation of the root package entry, so neither a plain search-and-replace nor an indent-anchored one is safe. Edit only the top-level `version` (line 3) and the root package entry under `packages` → `""` (line 9), by line position, and diff before committing — a correct bump is exactly 3 changed lines across `package.json` and `package-lock.json`. Do not run `npm install` or `npm audit fix` to do it (see DECISIONS.md on the byte-identical preset exports). Found during the `1.3.1` bump (`2c35f4c`).
- **`npm run build` leaves `apps/web/next-env.d.ts` modified, and committing it flips the dev typecheck path** → the production build rewrites its third line from `/// <reference path="./.next-dev/types/routes.d.ts" />` to `./.next/types/routes.d.ts`, because `next.config.ts` gives development and production different `distDir` values (`.next-dev` vs `.next`) and Next regenerates the file to match whichever build just ran. The file says "This file should not be edited", so it is easy to assume it is inert and sweep it into a `git add -A`. `git checkout -- apps/web/next-env.d.ts` after any production build, and check `git status` before committing — a verification build should leave no trace. Found while running a standalone production build to verify the project-thumbnail Host-header fix (2026-09-09).
- **`git push` prompts for credentials** → the remote should be SSH, not HTTPS: `git@github.com:marlin1111ai/marlin-cad.git`.
- **Unraid pull fails with "unauthorized" or "manifest unknown"** → the GHCR package is private. Make it public at `github.com/users/marlin1111ai/packages/container/marlin-cad/settings`, or log Unraid in to ghcr.io. GHCR reports "package does not exist" and "you may not read it" identically, so this misreads as a typo'd tag.
- **Docker build produces no `apps/web/server.js`** → `next.config.ts` only emits `output: "standalone"` when `SKETCHFORGE_DOCKER_BUILD=true`; the Dockerfile must set it or the runtime COPY has nothing to copy. Related trap in the same build: standalone output does **not** carry `public/` across, so the OCCT WASM (~22MB in `apps/web/public/occt/`) needs its own explicit `COPY` — miss it and the app boots fine but the STEP exporter 404s at runtime.
- **`claude: command not found` right after the native installer runs** → `~/.local/bin` isn't on PATH. `echo 'export PATH="$HOME/.local/bin:$PATH"' >> ~/.bashrc && source ~/.bashrc`.
- **`Host key verification failed` on a fresh box** → `~/.ssh/known_hosts` doesn't exist yet, so the first git/ssh contact with GitHub has nothing to check against. `ssh-keyscan -t rsa,ecdsa,ed25519 github.com >> ~/.ssh/known_hosts`, and verify the ed25519 fingerprint is `SHA256:+DiY3wvvV6TuJJhbpZisF/zLDA0zPMSvHdkr4UvCOqU` before trusting it.
- **GitHub Actions never runs on this repo, even on every push** → the repo is a fork of `Formsmith746/SketchForge-3D`, and GitHub disables workflows by default on a fork that already contained workflow files. Open the repo's Actions tab and click "I understand my workflows, go ahead and enable them" (or Settings → Actions → General → Actions permissions if that banner isn't there).
- **Docker workflow fails at the push step with `denied: permission_denied: write_package`** → two settings are needed together: Settings → Actions → General → Workflow permissions → "Read and write permissions", and the package's own settings at `github.com/users/marlin1111ai/packages/container/marlin-cad/settings` → Manage Actions access → Add Repository `marlin-cad` → role Write.
- **`marlin-cad` container missing from the Unraid Docker tab** → recreate it with the settings recorded in SESSION-STATE.md's Production deployment section (image tag, port mapping, volume mapping). This has now happened **twice**: once before the `1.1.0` deployment, and again on 2026-09-07 during the `1.3.1` update. The cause is unrecorded on both occasions. Recreating by hand from the recorded settings restored it both times, and because the projects volume is mapped to `/mnt/user/appdata/marlin-cad/projects` on the host, no project data was lost either time.
- **Docker Manager icon blinks / shows a question mark on Unraid** → `cp /mnt/user/appdata/marlin-cad/freecad.png /usr/local/emhttp/plugins/dynamix.docker.manager/images/question.png`. This is RAM-only and is lost on reboot; the permanent fix is a web-hosted Icon URL on the container's settings.
- **The dev app loads broken in a browser on another machine (the owner's Mac)** → plain `npm run dev` answers a browser on another machine with 403 for the app's scripts (`/_next/*`), and the dev server logs "Blocked cross-origin request". Start it as `SKETCHFORGE_ALLOWED_DEV_ORIGINS=192.168.1.245 npm run dev`; `apps/web/next.config.ts` reads the extra allowed origins from that variable, so no file is edited. Found in the build pass (`bf755c5`); see `reference/reports/viewport-mouse-controls-build.md` section 8.
- **A pasted shape comes out bare: a Gridfinity Socket Tray pasted with no holes and no labels, at the default 3 × 2 squares, Corner Radius 0 and raised labels** → paste (Ctrl / Cmd + C then V, Ctrl / Cmd + X then V, and the toolbar's Copy and Paste) read the clipboard back through `parseClipboardShapes` (`apps/web/src/components/SketchForgeEditor.tsx`), which rebuilt each shape with `sceneShape` (`apps/web/src/lib/shapeCatalog.ts`). `sceneShape` keeps only the basic fields, so every primitive's own fields were dropped: the Gridfinity tray's squares, corner radius, label style and holes, and in the same way the fields of the OpenGrid Board, OpenConnect Container, OpenGrid Snap, Multiconnect Container and Wrench Racks, and all four other trays, plus mirror flags and edge treatments. Width, depth and height survived, which is why the outline could look right. Duplicate (toolbar and Ctrl + D) copies the shape directly and was never affected. Fixed by spreading the parsed shape back over `sceneShape`'s defaults in `parseClipboardShapes`; `sceneShape` itself is unchanged. Checked live through every route, before and after, and by exporting the original and the pasted copy through the STL writer (same 20,780 facets, 0 boundary and 0 non-manifold edges). Commit `877951f`, 2026-09-29.
